# 上肢目标速度软惩罚与权重标定

当前配置：`target_speed.soft_limit=2.5 rad/s`、`weight=-0.002`。
固定底座与Mobile共用`RewardsCfg`，该设置覆盖腰部3关节和双臂14关节。
本次仅启用已有奖励函数，保持现有动作映射和执行方式。

## 1. 实际惩罚的量

当前控制周期`h=1/60 s`，关节位置动作为`q_target=q_default+0.5*a`。
动作项在每次处理目标时记录：

```text
v_target[j,t] = (q_target[j,t] - q_target[j,t-1]) / h
c[t] = sum_j(max(abs(v_target[j,t]) / 2.5 - 1, 0)^2)
r[t] = -0.002 * c[t] * h
```

函数返回未加权的`c`；RewardManager统一施加权重与控制周期，步长只乘一次。
相邻位置目标的速度是指令变化速度，与实际关节转速分别理解。
2.5 rad/s以内不增加该项罚分，超过后按超出比例平方增长。

每个回合重置时，物理关节和PD目标同步到默认状态，目标速度的历史也以新PD目标为起点。
因此首个策略目标造成的跳变会计入惩罚。

## 2. 为什么短时间爆冲仍会产生明显代价

设一个关节在一帧内改变目标`d` rad，正数`lambda=0.002`为惩罚权重绝对值：

```text
单帧罚分 = -lambda * h * max(d / (2.5*h) - 1, 0)^2
         = -lambda / (2.5^2*h) * max(d - 2.5*h, 0)^2
```

对于固定目标位移，大幅跳变的代价近似与`d²/h`成正比。
速度平方的增长抵消了持续时间短的影响，因此单帧大幅阶跃仍能被直接惩罚。

| 单关节一帧目标位移 | 目标变化速度 | 该帧新增罚分 |
|---|---:|---:|
| 0.04167 rad及以内 | 2.5 rad/s及以内 | 0 |
| 0.10 rad | 6 rad/s | −0.0000653 |
| 0.25 rad | 15 rad/s | −0.000833 |
| 0.50 rad | 30 rad/s | −0.00403 |
| 1.00 rad | 60 rad/s | −0.01763 |
| 2.00 rad | 120 rad/s | −0.07363 |
| 3.00 rad | 180 rad/s | −0.16803 |

多个关节的代价直接相加。
表中也表明：该权重主要针对极端、大幅或多关节跳变；单关节中等幅度的快速运动仍属于较温和的软约束。

进一步，将同一目标位移`d`均匀分配到时长`T`：

```text
总罚分 = -lambda * T * max(d / (2.5*T) - 1, 0)^2
```

| 单关节完成1 rad目标变化的时间 | 总罚分 |
|---|---:|
| 16.7 ms，1控制步 | −0.01763 |
| 33.3 ms，2控制步 | −0.00807 |
| 100 ms，6控制步 | −0.00180 |
| 200 ms，12控制步 | −0.00040 |
| 400 ms，24控制步 | 0 |

上述推导固定的是目标位移。若峰值速度固定，仅减少持续时间，积分代价会随时间减少，这是另一种比较。
策略到位后保持目标会使后续该项为0，但不会退还前面已经产生的负回报。
回合平均日志会稀释短时峰值，PPO接收的则是逐步奖励。

## 3. 为什么初值选择−0.002

现有Mobile上肢动作变化代价为`-0.03 * sum((delta_a)^2)`。
在60 Hz、动作比例0.5下，`v_target=30*delta_a`，因此大幅跳变时：

```text
target_speed代价 ≈ -lambda * 144 * sum((delta_a)^2)
与action_rate的额外代价比 ≈ lambda * 144 / 0.03
```

希望对极端跳变提供约10倍于现有动作变化项的额外代价，对应：

```text
lambda ≈ 10 * 0.03 / 144 = 0.0020833
取便于配置的0.002，额外代价比约9.6倍。
```

该倍数是大幅跳变的渐近值；在软阈值附近，新增代价较小，阈值以内为0。
因此比直接把全局`action_rate`提高10倍更集中于过快的指令变化。
这是有量级依据的初值，最优权重仍由相同条件下的新训练决定。

## 4. 已有失败轨迹的离线重算

使用`outputs/failures/planar_mean`的100个旧版失败片段，模型为`2026-11-17_10-53-14/model_7999.pt`，level 0、mean输出。
采集配置确认：Upper动作比例0.5、无动作裁剪，前6维为Lower命令，后17维为Upper关节动作。
其中89个片段从回合首个控制步开始，可重建完整目标差分；其余11个的首次未知目标变化不用于完整回合统计。

按当前新权重重算89个完整片段：

| 新增惩罚绝对值 | P25 | 中位数 | P75 |
|---|---:|---:|---:|
| 首个控制步 | 0.324 | 0.370 | 0.439 |
| 整个记录回合累计 | 0.448 | 0.513 | 0.588 |

代表样本`000003`：

- 首帧最大目标变化速度约178 rad/s；这是位置指令变化速度。
- 首帧新增罚分约−0.438，原有该帧`action_rate`约−0.0480，约9.13倍。
- 至0.167 s失败，整段新增累计罚分约−0.572。

当前正奖励理论上界约3.0/s：位置2.0、朝向0.6、Q 0.2、Dwell 0.2。
每个控制步最高约+0.05；上述首帧惩罚中位数约相当于7.4个满分控制步的正回报。
这些额外代价已足以与提前约0.1–0.2秒到点的收益处于相近量级，同时还有原有实际运动及失败代价。

这里是对固定旧动作序列的反事实奖励计算，仅说明惩罚强度。
失败样本存在选择偏差，不能据此推断正常回合平均罚分、最新模型的动作分布或训练后的失败率改善。
原始逐样本结果和复现脚本见`reports/upper_target_speed_2026-11-17/`。

## 5. 验证重点与作用边界

- 优先看目标切换后的指令变化速度峰值、实际关节速度、基座倾斜、首次接触时间和任务到达质量。
- `Episode_Reward/target_speed`变得接近0，需结合上述峰值判断，避免只看回合平均。
- 一次目标跳变后保持目标，该项后续为0；关节继续运动时，由现有`joint_vel`及加速度项继续约束。
- 仅由外力、接触等造成的实际速度尖峰可能不伴随目标跳变，使用实际运动指标判断。
- 本项也会惩罚随机动作探索的跳变；评估时区分mean输出与sample输出。
- 它是训练软约束。当前未引入参考限速器，也未增加速度终止条件；部署沿用原执行链。

现有单元回归覆盖阈值、正负方向、步长与权重只施加一次、局部重置、首帧跳变，以及固定目标位移在更短时间完成时的代价增长。
