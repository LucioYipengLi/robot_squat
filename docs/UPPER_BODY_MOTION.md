# 上肢渐进扰动

训练默认使用 `quintic_v1`：随机事件采样最终姿态，共享运动组件逐步生成位置和速度参考，现有隐式 PD 执行器追踪参考。双臂和腰部仍属于外部扰动，策略动作维度和下肢映射保持原样。

## 配置与使用

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `env.upper_body_motion.profile` | `quintic_v1` | 渐进参考；`step_v1` 为历史阶跃基线 |
| `env.upper_body_motion.max_velocity` | `2.5` rad/s | 每个关节的参考速度上限 |
| `env.upper_body_motion.max_acceleration` | `8.0` rad/s² | 每个关节的参考加速度上限 |
| `env.upper_body_motion.min_duration_s` | `0.3` s | 一段运动的最短时长 |

上述为当前训练配置；内置 v2 评估 suite 显式使用 `2.0 rad/s`、`8.0 rad/s²`、`0.5 s`，以 suite 中的值为准。执行器沿用现有增益，真实关节响应仍受惯量、接触及 PD 影响。

原 train/play 命令可直接增加这些覆盖项，例如：

```text
env.upper_body_motion.max_velocity=1.5 env.upper_body_motion.max_acceleration=6.0
```

正常 play 使用名义无扰动配置。观察扰动时使用 `--train_env_cfg`，并根据实验需要冻结课程。目标幅度依然由事件的 `joint_noise_frac` 控制，采样间隔仍为 1.5～3 秒。

双臂幅度课程保留原存活 EMA，并增加全局联合成功率门槛：`survival_ema > 0.95` 且 `task_success_rate > 0.8` 时，按原有每至少 2000 控制步检查、每次增加 0.005 的规则推进，上限仍为 0.8。联合成功率复用现有回合判定，取各环境最近一个有效已结束回合的均值，独立于日志窗口；恢复训练时重新收集。任一条件不足时保持当前幅度，存活 EMA 继续更新。

新增门槛通过 `env.curriculum.upper_body_disturbance_magnitude.params.task_success_gate` 调整，`0.8` 为待正式训练校准的初值。对应日志含义见 [课程信号](TRAINING_METRICS.md#4-课程信号为什么训练条件变化)。

渐进扰动评估使用 `g1_core_v2`、`g1_robustness_v2`，省略 `--suite` 时默认选择 `g1_core_v2`。v2 的任务范围、预算、阈值及幅度扫描点沿用 v1；新增运动配置参与 manifest 哈希，并写入有效环境配置、结果元数据和新训练检查点的课程元数据。

`g1_core_v1`、`g1_robustness_v1` 保留 `step_v1`，用于阶跃基线复测。两种参考方式共享已修复的重置行为。旧报告保留原含义；重新运行当前 v1 也包含重置修复及当前物理版本，复现时需核对源码与仿真版本。

## 运动规则

每个环境独立维护一个运行段和一个最新待执行目标，17 个上肢关节共享该段时长。事件只采样目标，执行器参考只由共享组件发布。

1. 空闲环境收到目标后，在下一次动作执行时开始运动。
2. 运行中收到目标，先完成当前段；后续采样只替换待执行目标。
3. 当前段以零参考速度和零参考加速度结束，下一次动作执行时开始待执行段。
4. 相同目标不产生额外运动段。回合重置清空运行段、待执行目标和统计。

参考公式为 `q_ref = q_start + (q_goal - q_start) × (10s³ - 15s⁴ + 6s⁵)`。其中 `s` 从 0 增长到 1，速度使用该公式的解析导数。按整段最大关节位移 `d` 选择时长：

```text
T = max(min_duration_s,
        1.875 × d / max_velocity,
        sqrt((10 / sqrt(3)) × d / max_acceleration))
```

这约束参考曲线的连续时间峰值。离散执行在首个到达终点的物理调用结束该段，实际占用时长可能比 T 多不足一个调用间隔。

当前 PhysX 配置每 8.33 ms 更新一次参考。由后端内部处理抽帧时，按实际动作调用间隔推进，保证计时一致。CUDA float32 使用一个 Warp kernel 更新整批环境；CPU 和数值对照使用张量实现，二者有逐步等价性测试。

## 观测与续训

`upper_body_target` 默认读取**最终目标相对默认姿态的偏移**，配置为 `env.observations.policy.upper_body_target.params.target_source=final_goal`。17 维、关节顺序、噪声、历史长度和函数入口保持原样；执行器继续追踪渐进位置参考 `q_ref` 和速度参考。

| 运动状态 | 策略读取的目标 | 观察含义 |
| --- | --- | --- |
| 空闲，已有待执行目标 B | `pending_goal=B` | 下一次动作应用前可获知 B |
| 正在向 A 运动 | `goal=A` | 持续提示当前段终点 |
| 正在向 A 运动，B 在排队 | `goal=A` | 后续采样只替换排队目标，当前段终点保持稳定 |
| A 结束，B 等待启动 | `pending_goal=B` | 显示下一段终点，读取本身不启动运动 |
| 空闲，无待执行目标 | `goal` | 保持已完成的终点；重置后等于本回合实际重置姿态 |

只有 `pending=True` 时待执行缓冲才有效。观测只选择数据源，采样、轨迹推进、接续和执行器写入的顺序保持原样。当前控制步约 16.67 ms，参考每约 8.33 ms 更新；同一控制步内完成 A 并启动 B 时，策略可能在 B 已运行一个物理步后收到新观测。实际提示提前量由采样和控制时序决定。

需要复测此前渐进参考观测的模型时，train/play 可显式设置 `env.observations.policy.upper_body_target.params.target_source=reference`，此时读取当前 PD 参考。`step_v1` 的两种来源均读取已经发布的阶跃目标，避免读取未更新的渐进轨迹缓存。

动作扩展沿用 IsaacLab 的下肢缩放、偏置、裁剪和关节选择。eval 仅对已知的原关节位置动作类与该扩展做等价归一化，其他配置差异继续严格校验。

新检查点课程元数据、有效环境配置和 eval 结果均记录 `upper_body_target_source`。eval 对等维度的来源变化进行校验：历史阶跃模型按 `final_goal` 解释；缺少来源标记的历史 `quintic_v1` 模型按 `reference` 解释。自定义 suite 可通过 `benchmark.upper_body_target_source: reference` 复测后者，此字段参与 manifest 哈希。

旧检查点可作为新观测和扰动条件下的续训起点。课程比例和进度按原有规则恢复，观测来源使用本次训练配置；轨迹随新回合初始化。使用新 run 名称记录条件变化。训练可据此适应新观测，eval 则要求检查点与测试的观测语义一致。

## 统计如何判断

原有扰动次数、频率继续表示**目标采样事件**，逐步执行另外记录以下信息。

| 训练日志 `UpperBodyMotion/` | 含义 |
| --- | --- |
| `started_per_episode` | 本次重置环境平均开始执行的运动段数 |
| `pending_replaced_per_episode` | 平均被后续采样替换的待执行目标数 |
| `reference_completion_rate` | 有运动回合的完成段数 / 开始段数，再按回合平均；回合结束时仍在运行的段计为未完成 |
| `mean_planned_duration_s` | 先计算每个有运动回合的平均计划时长，再按回合平均 |

这些训练诊断在回合边界汇总；初次空回合可能产生零计数。eval 的 JSON/CSV 额外保留 `motion_started`、`motion_completed`、`motion_pending_replaced`、`motion_duration_sum_s`、`motion_time_s`。汇总时先合并计数再计算比例，并在 TensorBoard 的“04 测试条件”展示：

- **实际运动频率**：开始段数 / 实际回合总时长。
- **参考到达率**：完成段数 / 开始段数，表示参考到达最终目标；真实关节跟踪精度需另行测量。
- **平均计划运动时长**：计划时长总和 / 开始段数。
- **待执行目标替换数 / 回合**：替换次数 / 回合数。

待执行替换频繁，通常说明运动时长相对于采样间隔偏长。比较模型时，同时核对实际运动频率、时长和参考到达率，确认有效扰动暴露接近。零开始段时，到达率和平均时长保持未定义。

## 模块 review 与验证边界

| 模块 | Review 结论 |
| --- | --- |
| 数值轨迹 | 起止参考速度、加速度为零；解析时长满足参考峰值约束；接续及局部重置隔离有测试 |
| GPU 执行 | 每环境由一个线程管理状态，避免标志与关节更新竞态；与 Torch 使用同一 CUDA stream |
| 动作与重置 | 下肢映射委托原实现；在动作应用前后保持既有物理步顺序；重置同步位置、速度、力矩与轨迹状态 |
| 最终目标观测 | 运行中读取段终点，空闲时预览有效待执行目标；读取不改变轨迹、执行器命令或随机数状态 |
| 训练与 eval | 共用目标执行器；采样时钟保持各自原规则；新增执行统计区分采样与运动 |
| 幅度课程 | 保留存活 EMA，增加全局联合成功率门槛；缓存与日志窗口独立，续训清空后重建 |
| 兼容性 | 保持网络形状；动作兼容范围限定为已知类；运动版本、参数和观测来源可追溯 |

维护重点是轨迹规则与两种数值执行的一致性，相关测试覆盖 GPU/Torch 对照、待执行替换、零位移、局部重置和旧动作兼容。

测试脚本：`tests/_upper_body_motion_physics.py` 验证小规模真实 PhysX 步进、最终目标观测与重置，结果写入 `outputs/verification/goal_observation_physics.json`；`tests/_benchmark_trajectory.py` 测量 4096×17 的纯轨迹更新耗时与状态内存。后者不含目标写入、物理求解和 PPO，完整训练吞吐需要独立测量。

## 总体 review 与实测记录

2026-10-21 完成以下验证：

- 最终目标观测调整后，334 项非仿真回归通过，包括 CPU/CUDA 观测只读性、轨迹数值对照、旧观测来源识别、配置哈希和续训来源记录；Ruff 与 diff 空白检查通过。
- 幅度课程门控调整后，354 项非仿真回归通过，覆盖成功判定复用、缓存与日志隔离、双门槛边界、原 EMA 数值、结算时序和旧检查点恢复；Ruff 与格式检查通过。P1 的过时注释与 docstring 同步修正，扰动实现维持原结构。
- 真实 headless PhysX：4 个 G1 环境、90 个控制步，验证首次目标预览、运行中保持当前终点、两段接续、参考目标写入及局部重置。参考峰值速度约 1.394 rad/s、峰值加速度约 7.984 rad/s²，均在本次 v2 配置范围内。
- v2 端到端评估：合成策略运行基础跟踪与扰动扫描两个模块，共 8 回合，产出逐回合记录、汇总及 TensorBoard 日志；这是链路验证。
- RTX 5060 Ti 上，4096×17 轨迹在全运动负载下三次计时约 0.036～0.073 ms/次，持久状态约 1.46 MiB。首次 kernel 加载/编译单独计入启动开销，计时前预热。

总体影响：网络形状与下肢动作映射保持原样；训练扰动的动力学、目标提示方式和有效姿态覆盖发生变化，使用新 run 与版本化 suite 记录。维护新增一个参考算法及其 GPU 执行，两者由数值对照测试约束一致性。

本次观测调整的范围为数据源选择及相关配置、元数据、兼容性校验和文档。轨迹算法、GPU kernel、采样规则与动作执行时序沿用上一版；运行时增加批量目标选择，学习收益由后续正式训练与同条件评估检验。

完整 PPO 训练 FPS 降幅尚未实测；上述 kernel 基准不能直接换算为训练吞吐。真实关节峰值、接触冲击和学习收益需要结合后续执行器参数复核与正式训练评价。
